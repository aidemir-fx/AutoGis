# Спецификация: модальное окно «Оставить заявку» (частный мастер + автосервис)

## 1) Цель
Реализовать единое модальное окно отправки заявки для двух типов исполнителей:
- частный мастер;
- автосервис.

Окно открывается по кнопке «Оставить заявку» и позволяет клиенту заполнить данные для обращения.

## 2) Scope
В рамках этой задачи:
- UI/UX модального окна заявки;
- валидация полей на клиенте;
- автоподстановка данных профиля;
- отправка заявки в API;
- прикрепление фотографий к заявке.

Вне scope:
- логика чата;
- назначение точного времени выполнения;
- изменение статусов заявки после создания.

## 3) Единый сценарий
1. Пользователь нажимает кнопку «Оставить заявку» в карточке исполнителя.
2. Открывается модальное окно.
3. Пользователь заполняет обязательные поля и при необходимости добавляет фото.
4. Нажимает «Отправить заявку».
5. При успехе: модалка закрывается, показывается сообщение об успешной отправке.
6. Заявка появляется у исполнителя в списке заявок.

## 4) Поля формы
## 4.1 Состав полей
1. `name` — Имя
2. `phone` — Номер телефона
3. `carBrand` — Марка автомобиля
4. `timePreference` — Предпочтение по времени
5. `description` — Описание проблемы (свободный ввод)
6. `photos` — Фотографии (опционально)

## 4.2 Обязательность
- Обязательные: `name`, `phone`, `carBrand`, `timePreference`, `description`.
- Необязательное: `photos`.

## 4.4 Предпочтение по времени
Поле `timePreference` — выбор из 2 вариантов:
- `urgent` — «Срочно»
- `not_urgent` — «Не срочно»

Под полем обязательно отображать предупреждение:
- «Точные дату и время записи укажет мастер после принятия заявки».

## 4.3 Автоподстановка
Если в профиле пользователя уже есть значения:
- `name` заполняется автоматически;
- `phone` заполняется автоматически.

Правила автоподстановки:
- автоподстановка происходит при открытии модалки;
- пользователь может отредактировать подставленные значения перед отправкой;
- при повторном открытии модалки подставляются актуальные значения профиля.

## 5) Валидация
## 5.1 Поле `name`
- минимум 2 символа;
- максимум 100 символов;
- ошибка: «Укажите имя».

## 5.2 Поле `phone`
- допустимые символы: цифры, пробел, `+`, `-`, `(`, `)`;
- после нормализации минимум 11 цифр;
- ошибка: «Введите корректный номер телефона».

## 5.3 Поле `carBrand`
- текстовое поле;
- минимум 2 символа;
- максимум 50 символов;
- ошибка: «Укажите марку автомобиля».

## 5.4 Поле `description`
- свободный ввод;
- минимум 10 символов;
- максимум 2000 символов;
- ошибка: «Опишите проблему (минимум 10 символов)».

## 5.5 Поле `photos`
- до 10 файлов;
- допустимые форматы: `jpg`, `jpeg`, `png`, `webp`;
- максимальный размер одного файла: 10 MB;
- ошибка формата: «Допустимые форматы: JPG, PNG, WebP»;
- ошибка размера: «Размер файла не должен превышать 10 MB»;
- ошибка количества: «Можно прикрепить не более 10 фотографий».

## 6) UX модального окна
## 6.1 Структура
- Заголовок: «Оставить заявку».
- Подзаголовок: «Заполните информацию для записи к {имя исполнителя}».
- Контент: поля формы по порядку из раздела 4.
- Нижняя панель: кнопки `Отмена` и `Отправить заявку`.
- В модалке (под полем `timePreference`) показывается предупреждение:
  «Точные дату и время записи укажет мастер после принятия заявки».

## 6.2 Поведение кнопок
- `Отмена`: закрывает модалку, несохраненные изменения сбрасываются.
- `Отправить заявку`:
  - неактивна, пока обязательные поля невалидны;
  - при отправке показывает состояние загрузки и блокирует повторный клик.

## 6.3 Блок фотографий
- Кнопка «Прикрепить фотографии»;
- предпросмотр миниатюр выбранных фото;
- возможность удалить каждую фотографию до отправки.

## 7) API-контракт
## 7.1 Создание заявки
`POST /orders`

Тело запроса:
- `providerId: string (uuid)`
- `activityTypeId: string (uuid)`
- `name: string`
- `phone: string`
- `carBrand: string`
- `timePreference: "urgent" | "not_urgent"`
- `description: string`
- `photoAssetIds: string[]` (опционально)

Пример:
```json
{
  "providerId": "uuid",
  "activityTypeId": "uuid",
  "name": "Иван",
  "phone": "+7 999 123-45-67",
  "carBrand": "Toyota",
  "timePreference": "urgent",
  "description": "Посторонний стук в подвеске при движении",
  "photoAssetIds": ["asset-1", "asset-2"]
}
```

## 7.2 Загрузка фото
Фото загружаются отдельно через текущий медиа-пайплайн проекта.
В заявку передаются только идентификаторы уже загруженных файлов (`photoAssetIds`).

## 7.3 Ответ API
В объекте заявки должны возвращаться:
- `name`
- `phone`
- `carBrand`
- `timePreference`
- `description`
- `photos` (или `photoAssetIds` + ссылки на фото)
- служебные поля заявки (`id`, `status`, `createdAt` и т.д.)

## 8) Модель данных заявки
Добавить/поддержать поля:
- `name` (string)
- `phone` (string)
- `carBrand` (string)
- `timePreference` (enum: `urgent` | `not_urgent`)
- `description` (text)
- `photoAssetIds` (array<string>) или связь с media table

Важно:
- структура едина для заявок частному мастеру и автосервису;
- тип исполнителя определяется существующими полями (`providerId`, `activityTypeId`), отдельный тип заявки не вводится.

## 9) Обработка ошибок
- Ошибки валидации полей показываются под соответствующим полем.
- Ошибка отправки заявки:
  - toast: «Ошибка при отправке заявки».
- Ошибка загрузки фото:
  - toast: «Не удалось загрузить фотографию. Попробуйте ещё раз».

## 10) Безопасность и ограничения
- На сервере повторно валидировать все поля независимо от фронта.
- Проверять принадлежность `photoAssetIds` текущему пользователю до привязки к заявке.
- Не допускать привязку неподтвержденных/невалидных медиа-файлов.

## 11) Критерии приёмки (QA)
1. Модалка открывается по кнопке «Оставить заявку» для частного мастера и автосервиса.
2. Поля `name` и `phone` автоматически подставляются из профиля при наличии.
3. Пользователь может изменить автоподставленные значения.
4. Без обязательных полей заявка не отправляется.
5. Поле `timePreference` обязательно и позволяет выбрать только «Срочно» или «Не срочно».
6. Под полем `timePreference` отображается предупреждение, что точные дату и время назначает мастер.
7. `description` принимает свободный ввод и валидируется по минимальной длине.
8. Фото можно добавить, увидеть в предпросмотре и удалить до отправки.
9. При успешной отправке показывается успех и модалка закрывается.
10. У исполнителя заявка отображается с заполненными данными (`name`, `phone`, `carBrand`, `timePreference`, `description`, фото).
11. Один и тот же формат заявки работает для частного мастера и автосервиса без разветвления UI.

## 12) Технические примечания
- Рекомендуется переиспользовать текущий модуль модального окна создания заявки и расширить его новыми полями.
- Для фото использовать уже существующий в проекте модуль загрузки медиа, чтобы не дублировать реализацию.
